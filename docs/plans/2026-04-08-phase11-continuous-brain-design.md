# Phase 11: 连续循环脑架构升级设计

> 日期: 2026-04-09（最终确认版）
> 状态: 设计已确认

## 一、设计目标

将 AI Brain Agent 从"单次查询→单次响应"的 demo 玩具，升级为**像人脑一样不间断执行任务的连续循环系统**。

核心变化：
- 从一次 query() 结束 → 到持续循环直到任务完成
- 从广播给所有副脑 → 到感知脑拆解 + 推理脑主导执行
- 从硬编码流程 → 到技能/MCP/插件驱动的灵活工作流
- 任务范围：通用 AI Agent（编码/写作/信息收集/图片处理/视频剪辑等）

---

## 二、副脑精简：6 → 4

| 副脑 | 职责 | 变化 |
|------|------|------|
| **感知脑** | 入口：理解任务、拆解步骤、推荐工具 | 职责大增：新增拆解 + 工具推荐 |
| **主脑** | 编排：计划管理、澄清循环、步骤推进、完成度评估 | 职责变化：从单次 run_once → 澄清循环 + Plan 循环 |
| **推理脑** | 主执行者：LLM ↔ 工具调用循环 | 职责大增：合并执行脑，直接调工具 |
| **记忆脑** | 存储：主动注入、权重召回、上下文压缩、跨会话持久化 | 职责大增：主动注入 + 上下文压缩 + Plan 持久化 |

**删除的副脑：**
- 执行脑 → 合并到推理脑（推理脑直接调工具）
- 校验脑 → 降级为工具调用前置 guard_check() 函数
- 评估脑 → 评估职责归主脑 evaluate_step()，上下文瘦身归记忆脑
- 进化脑 → 暂时不需要，性能数据记在记忆脑

## 三、三阶段完整数据流

### Phase 1: 感知 (Perceive)

```
用户输入 "写一个计算器" → 感知脑:
  ① LLM 理解任务意图
  ② LLM 自主拆解为步骤列表（不依赖技能）
  ③ 查询资源池（技能库 + MCP + 插件）
  ④ 根据任务 + 拆解内容 → 推荐 top 5 工具
  输出: TaskPlan {
    status: Draft,
    steps: [调研方案, 设计架构, 编码实现, 测试验证],
    recommended_tools: [TDD skill, filesystem MCP, bash MCP, ...],
  }
```

### Phase 2: 澄清循环（四脑协作，直到每步都清晰无歧义）

```
第1轮:
  推理脑: 根据拆解结果，给出具体方案
      ↓
  记忆脑: 主动注入相关记忆 + 记录方案内容
      ↓
  主脑: 评估方案，然后询问推理脑
        "方案有没有歧义？不确定的？需要用户确认的？和用户设想有出入的？"
      ↓
  推理脑: 分析后返回 → "有3个问题：语言？界面？精度？"
      ↓
  记忆脑: 记录问题
      ↓
  主脑: 评估问题质量，将问题抛给用户
      ↓
  用户: "Rust，命令行，整数运算"
      ↓
  主脑: 将用户回答转给推理脑
      ↓
  记忆脑: 提取确认事实 → {语言:Rust, 界面:CLI, 精度:整数}，记录

第2轮:
  记忆脑: 主动注入确认事实 + 相关摘要（每轮都注入）
      ↓
  推理脑: 结合用户回答更新方案，继续推理
      ↓
  记忆脑: 记录更新后的方案
      ↓
  主脑: 再次评估 + 再次询问推理脑
      ↓
  推理脑: "除零怎么处理？"
      ↓
  主脑 → 用户 → 用户回答 → 主脑转给推理脑 → 记忆脑记录

... 循环直到推理脑确认无歧义 ...

最终:
  主脑: 评估通过，无待确认项
  TaskPlan.status → Confirmed ✓
```

### Phase 3: 确定性执行（每步清晰，不再有疑问）

```
主脑 for step in plan.steps:
  ① 记忆脑主动注入上下文（权重召回 + 确认事实）
  ② 分发当前 step 给推理脑（含推荐工具列表）
  ③ 推理脑执行 LLM ↔ 工具调用循环
     - LLM 思考 → 调工具 → 观察结果 → 继续思考
     - guard_check() 拦截高危操作 → 需确认的弹给用户
     - 步骤内记忆脑持续主动注入
  ④ 推理脑输出 step_result
  ⑤ 主脑 evaluate_step() 评估完成度
     - 量化指标（文件存在/编译通过/测试通过）
     - LLM 质量评分（0-1）
     - 判定: PASS → 下一步 / FAIL → 重试或调整
  ⑥ 记忆脑持久化（step_result + 工具调用记录）
  ⑦ 步骤间 → 记忆脑压缩本步骤的工具调用历史
  ⑧ 下一个 step...（循环）

所有 steps 完成 → 主脑最终评估 → 输出结果给用户
```

## 四、记忆脑设计（核心）

### 4.1 设计原则

**类比人脑海马体**：主动注入，不是被动查询。

- 海马体不需要前额叶主动问"之前决定了什么"
- 海马体自动把相关的确认事实和经验注入到工作记忆
- 推理脑永远不需要主动请求基础上下文——记忆脑保证始终存在

### 4.2 记忆三层结构

```
记忆脑 (MemoryBrain)
│
├── 确认事实注册表 (ConfirmedFacts) — 语义记忆
│   {语言: Rust}              ← 第1轮确认
│   {界面: 命令行}             ← 第1轮确认
│   {错误处理: Result<T,E>}   ← 第3轮确认
│   特点: 只增不改，结构化，精炼，~50 tokens/条
│   注入: 始终完整注入（作为对话消息追加，不改 System Prompt）
│
├── 对话情景记录 (Episodes) — 情景记忆
│   Round 1: 完整对话记录
│   Round 2: 完整对话记录
│   ...
│   特点: 完整记录，步骤完成后压缩，支持通过引用 ID 召回
│
└── 压缩摘要 (Summaries) — 情景记忆的压缩版
    Step 1 摘要: "完成了项目初始化，创建了 src/calc.rs..."
    Step 2 摘要: "实现了加减乘除函数，12个测试通过..."
    特点: 原文存在长期记忆中，摘要+引用 ID 可召回
```

### 4.3 记忆权重召回

```rust
struct MemoryScore {
    relevance: f64,    // 语义相关度 (LLM 判断，权重 0.4)
    recency: f64,      // 时效性衰减 (权重 0.2)
    importance: f64,   // 重要性: confirmed=1.0, code=0.8, explore=0.3 (权重 0.3)
    frequency: f64,    // 被召回频率 (权重 0.1)
}

fn weight(&self) -> f64 {
    0.4 * self.relevance + 0.2 * self.recency
  + 0.3 * self.importance + 0.1 * self.frequency
}
```

**注入策略（按权重分级）**：

| 权重 | 注入方式 | 说明 |
|------|---------|------|
| ≥ 0.8 | 完整注入 | 直接给原文，不要摘要 |
| 0.5 - 0.8 | 摘要注入 | 给摘要 + 引用 ID |
| 0.3 - 0.5 | 仅提及 | 一句话带过 + 引用 ID |
| < 0.3 | 不注入 | 跳过 |

**预算控制**：记忆注入区域最多占用 X tokens（可配置，默认 4000）。超限时按权重排序，低优先级的降级为摘要。

### 4.4 主动注入机制

记忆脑在**推理脑每次调用 LLM 前**都主动介入：

```rust
impl MemoryBrain {
    /// 每次推理脑思考前调用
    fn recall_for_context(&self, current_input: &str) -> InjectedContext {
        // 1. 语义匹配
        let scored = self.index.search(current_input)
            .into_iter()
            .map(|m| (m, self.compute_weight(m)))
            .collect::<Vec<_>>();

        // 2. 按权重分级，构建注入内容
        let mut injections = Vec::new();
        let mut budget = self.injection_budget; // 默认 4000 tokens

        for (memory, weight) in scored.sorted_by_weight() {
            match weight {
                w if w >= 0.8 => {
                    if budget >= memory.full_tokens {
                        injections.push(FullContent(memory));
                        budget -= memory.full_tokens;
                    } else {
                        injections.push(Summary(memory)); // 预算不够，降级
                    }
                }
                w if w >= 0.5 => injections.push(Summary(memory)),
                w if w >= 0.3 => injections.push(Mention(memory)),
                _ => {} // 不注入
            }
        }
        InjectedContext { injections }
    }

    /// 推理脑请求完整记录时调用（通过引用 ID）
    fn recall_full(&self, ref_id: &str) -> Option<String> {
        self.long_term_memory.get(ref_id)
    }
}
```

### 4.5 记忆召回生命周期

```
① 默认注入（记忆脑主动判断，按权重分级）
   高权重 → 完整内容
   中权重 → 摘要 + 引用 ID
   低权重 → 仅提及 + 引用 ID

② 推理脑需要更多细节（主动请求）
   "请召回 memory://step3/arith_impl"

③ 记忆脑按 ID 取回完整内容，追加到对话

④ 推理脑使用完整内容继续推理

⑤ 步骤完成 → 记忆脑统一压缩（包括召回的完整内容）
   完整内容回到摘要形式
   原始记录仍在长期记忆中，下次还能召回
```

## 五、上下文结构设计（缓存优化）

### 5.1 核心原则

1. **只追加，不修改** — 保护缓存前缀
2. **确认事实用对话消息** — 不改 System Prompt
3. **记忆注入用新消息** — 不替换旧注入
4. **压缩只在步骤之间** — 一次缓存断裂可接受
5. **越稳定的越靠前** — 从前到后稳定性递减

### 5.2 上下文消息结构

```
稳定性: 永不变化 → 只增不改 → 步骤间变 → 每轮变化
         ↓           ↓          ↓          ↓

┌─────────────────────────────────────────────────────┐
│  [System Prompt] 固定指令                              │  ← 永不修改，永久缓存
├─────────────────────────────────────────────────────┤
│  [User] "✓ 确认: 语言=Rust"                           │  ← 只追加，追加后永久缓存
│  [User] "✓ 确认: 界面=CLI"                            │
│  [User] "✓ 确认: 错误=Result"                         │
├─────────────────────────────────────────────────────┤
│  [System] "Step 1 摘要: 完成了项目初始化..."            │  ← 步骤间才变，步骤内缓存
│  [System] "Step 2 摘要: 实现了加减乘除函数..."          │
├─────────────────────────────────────────────────────┤
│  [Assistant] "我需要看 main.rs"                        │  ← 当前步骤对话，前缀缓存
│  [Tool] Read → 返回 200 行                            │
│  [Assistant] "写 calc.rs"                             │
│  [Tool] Write → 成功                                  │
│  ...当前步骤的工具调用历史...                           │
├─────────────────────────────────────────────────────┤
│  [User] "记忆注入:                                     │  ← 每轮新增，少量
│         完整记忆: fn add(a:i32,b:i32)->Result<...>{…}  │
│         摘要: 用户确认了除零返回Err                     │
│         引用: memory://confirmed/err_handling"         │
├─────────────────────────────────────────────────────┤
│  [User] "当前任务: 实现除法函数"                        │  ← 每轮新增，最少
└─────────────────────────────────────────────────────┘
```

### 5.3 缓存命中分析

```
步骤内 Round N 调用:
  [System Prompt]              ← 缓存命中 ✓（永不修改）
  [确认事实]                    ← 缓存命中 ✓（只追加）
  [步骤摘要]                    ← 缓存命中 ✓（步骤内不变）
  [Round 1 到 N-1 对话]        ← 缓存命中 ✓（追加模式）
  --- 以下新增，增量付费 ---
  [记忆注入]                    ← 新增 ~500-4000 tokens
  [当前任务]                    ← 新增 ~100-500 tokens

典型命中率: 90-97%
```

### 5.4 步骤间压缩与缓存

```
Step N 完成 → 记忆脑压缩:
  Step N 的全部工具调用 → 摘要 + 确认事实提取

Step N+1 开始:
  [System Prompt]                    ← 缓存 ✓
  [确认事实（可能新增几条）]           ← 缓存断裂点（一次）
  [Step 1..N 摘要]                   ← 缓存 ✓
  [Step N+1 第一轮对话]              ← 新增
  → 第一次调用全价，后续调用立刻缓存

一次缓存断裂代价 ≈ 2-3k tokens 全价
换来整个 Step 内的缓存命中（~20-50 次调用）
```

## 六、会话生命周期

### 6.1 设计原则

类比人脑：睡觉不等于失忆。新会话 = 新工作记忆，但记忆脑跨会话持久化。

### 6.2 会话模型

```
新会话启动:
  1. 记忆脑加载所有相关历史
  2. 主动注入: 最近任务摘要 + 确认事实 + 可用引用
  3. 推理脑拿到上下文，直接可用

新会话第一次调用:
  全价（~3-5k tokens），但只有一次
  第二次调用开始缓存命中

会话关闭:
  记忆脑完整持久化
  未完成任务状态保存
  会话摘要生成
```

### 6.3 跨会话持久化

| 内容 | 保留策略 |
|------|---------|
| 确认事实注册表 | 永久保留 |
| 任务历史摘要 | 永久保留 |
| 完整工具调用记录 | 永久保留（可召回） |
| 未完成任务状态 | 永久保留（可恢复） |
| 会话摘要 | 永久保留 |
| 经验路径库 | 永久保留 |

### 6.4 恢复场景

- 用户关闭后重新打开 → 注入上次状态，从断点继续
- 用户开始全新任务 → 注入历史摘要（供参考）+ 空白确认事实
- 进程崩溃 → 恢复到最后一次持久化的检查点

## 七、已确认的全部设计决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 执行模式 | 三阶段：感知→澄清循环→确定性执行 | 确保每步清晰后再执行 |
| 副脑数量 | 4 个（感知/主/推理/记忆） | 精简，每个不可替代 |
| 任务拆解 | 感知脑 LLM 自主拆解 | 技能只是可选参考 |
| 澄清循环 | 四脑协作，主脑询问推理脑检查歧义 | 推理脑分析质量更高 |
| 工具推荐 | 感知脑查资源池后推荐 top 5 | 副脑执行时优先使用推荐 |
| 工具调用 | 推理脑直接调工具 | 合并执行脑，效率高 |
| 记忆注入 | 主动注入，按权重分级 | 高权重完整注入，低权重摘要 |
| 记忆召回 | 按引用 ID 按需召回完整记录 | 召回后步骤结束统一压缩 |
| 上下文结构 | System→确认事实→步骤摘要→对话→记忆注入→任务 | 稳定内容靠前，优化缓存 |
| 缓存优化 | 只追加不修改，压缩只在步骤间 | 90-97% 缓存命中率 |
| 人工介入 | 关键节点确认 + 危险操作确认 | 安全与效率平衡 |
| 完成标准 | 混合：量化指标 + LLM 评分 | 两层保险 |
| 持久化 | 记忆脑负责一切，跨会话 | 中断恢复 + 历史延续 |
| 技能来源 | 内置核心 + 用户自定义 SKILL.md | 支持扩展 |
| 会话模型 | 新会话=新工作记忆，记忆脑跨会话 | 类比人脑睡觉不失忆 |

## 八、组件复用审计结论

详细审计见 `docs/exploration/` 目录。

### 可直接复用

| 组件 | 来源 |
|------|------|
| file_ops (Read/Write/Edit/Glob/Grep) | runtime |
| bash 执行器 | runtime |
| mvp_tool_specs() | tools |
| MCP McpServerManager | runtime/mcp_stdio |
| Plugin 执行 | plugins |
| Skill 发现 + frontmatter 解析 | commands |

### 需要改造

| 组件 | 改造内容 |
|------|---------|
| brain-llm ChatRequest | 增加 tools/tool_choice，content 升级为 Vec<ContentBlock> |
| brain-llm LlmProvider | 增加 stream_complete() |
| 感知脑 LlmProvider trait | 统一到 brain-llm |
| 消息总线 | 核心调用从通道改为直接方法调用 |

### 全新实现

| 组件 | 原因 |
|------|------|
| 推理脑 tool_use 循环 | 当前完全没有 |
| 记忆脑权重召回 + 主动注入 | 新设计，runtime::compact 不满足 |
| 记忆脑上下文压缩 | 需要智能判断+原文保存+可召回 |
| TaskPlan 数据结构 | 新概念 |
| 主脑澄清循环 | 当前只有单次 run_once |
| 感知脑任务拆解 + 工具推荐 | 当前只做输入解析 |
| guard_check() 函数 | 统一前置安全检查 |
| evaluate_step() 方法 | 混合评估 |
| 跨会话持久化 | 新需求 |
