# 记忆金字塔重构设计

> 日期: 2026-05-22
> 状态: 已确认，待实施
> 范围: brain-memory crate 全面重构

## 一、背景与问题

### 当前问题

记忆脑（brain-memory）的数据从 2.3GB 膨胀到清理后 32MB，根因是**追加式设计**而非**金字塔提炼**：

| 问题 | 根因 | 影响 |
|------|------|------|
| 用户画像 56KB（183条偏好） | `merge_dedup` 只做精确字符串匹配 | 语义变体全部保留 |
| 评估要求 10条中7条重复 | `add()` 精确匹配去重 | 同一规则换个说法就重复 |
| 短期记忆 337条中100条含工具残留 | `store_turns` 拼入 ToolCall 输出 | 噪音污染 |
| Step0 不覆盖 UserProfile 和 EvalRequirement | 迭代机制遗漏 | 这两种数据永不清理 |
| importance 衰减/强化全部空操作 | `reinforce()` 空实现 | 淘汰机制失效 |
| 短期记忆无容量淘汰 | `store()` 不检查容量 | max_entries=200 形同虚设 |
| 守护线程门槛过高 | min_new_summaries=10 | 实践中永远不触发 |

### 核心设计缺陷

**不是金字塔，是垃圾堆**。每层都在无脑追加，没有向上提炼的机制。唯一做对了的是潜意识叙事（Step5）：覆盖式更新，500字上限。

## 二、新设计：人格隔离的记忆金字塔

### 2.1 核心原则

1. **底层全量保存，越往上越浓缩**——每层都有容量上限，全量重生成
2. **融合而非追加**——没有的加，冲突的融合，互补的融合
3. **多人格完全隔离**——每个人格拥有独立的金字塔
4. **渐进式召回**——自顶向下，LLM 自主决定何时停止
5. **最顶层是潜意识**——覆盖式更新，即时注入

### 2.2 四层金字塔

```
                    ┌─────────────────┐
                    │   潜意识层 L4     │  记忆召回触发词
                    │   (Subconscious)  │  "做过红冲逻辑"、"修过XX bug"
                    ├─────────────────┤
                    │   记忆抽象层 L3    │  按任务类型汇总的经验
                    │   (Abstraction)   │  编码→工具替代方案；写作→去AI味技巧
                    │   + 索引          │
                    ├─────────────────┤
                    │   记忆摘要池 L2    │  按任务分类（非按会话）
                    │   (Summary Pool)  │  一个会话可拆多个任务
                    │   + 索引          │  多个会话可归同一任务
                    ├─────────────────┤
                    │   全量记忆基座 L1   │  原始对话全量保存
                    │   (Raw Pool)      │  多个会话的完整记录
                    └─────────────────┘
```

### 2.3 数据向上浓缩流程

```
L1 全量记忆基座
  │  LLM 按任务拆分、分类（跨会话合并同类任务）
  │  输出: task_id, task_type, summary, 关联的 L1 文件+段落
  ▼
L2 记忆摘要池
  │  LLM 按任务类型抽象汇总（编码/写作/多媒体...）
  │  输出: type → 问题点+处理方式的综合经验
  │  生成 L2→L1 索引（任务→L1文件段落映射）
  ▼
L3 记忆抽象层
  │  LLM 从 L3 经验中提取关键触发词/句子
  │  输出: 触发词列表（指向 L3 索引条目）
  │  生成 L3→L2 索引（类型→L2任务摘要映射）
  ▼
L4 潜意识层（触发词）
```

### 2.4 各层详细设计

#### L1 全量记忆基座 (Raw Pool)

- **存储**: 每个会话一个 JSONL 文件，全量保存原始对话
- **内容**: 用户消息、助手回复、工具调用、评估反馈
- **容量管理**: 无上限，永久保存
- **改动**: 移除 ToolCall 输出混入短期记忆的逻辑

#### L2 记忆摘要池 (Summary Pool)

- **存储**: 按任务分类的 JSON 文件
- **分类逻辑**: LLM 将会话内容拆分为独立任务（一个会话可拆出多个任务，多个会话的任务可合并）
- **索引文件**: `index.json`，内容为:
  ```json
  [
    {
      "task_id": "task-001",
      "task_type": "编码任务",
      "task_name": "TUI鼠标选择修复",
      "summary": "修复EnableMouseCapture拦截导致终端原生选择失效...",
      "l1_refs": [
        {"session": "sess-xxx", "paragraphs": [3, 4, 5]},
        {"session": "sess-yyy", "paragraphs": [1, 2]}
      ],
      "tags": ["TUI", "鼠标", "crossterm"],
      "importance": 0.85,
      "created_at": "2026-05-12T...",
      "updated_at": "2026-05-12T..."
    }
  ]
  ```
- **容量管理**: 全量重生成（覆盖式），不追加
- **排序**: 按 importance + 时间降序

#### L3 记忆抽象层 (Abstraction Layer)

- **存储**: 按任务类型分类的经验文件
- **内容结构**:
  ```json
  {
    "type": "编码任务",
    "experiences": [
      {
        "pattern": "工具调用失败时的替代方案",
        "description": "WebSearch工具调用失败时，可用bash+curl替代获取网页内容",
        "source_tasks": ["task-001", "task-007"],
        "frequency": 3,
        "injectable": true
      }
    ],
    "l2_refs": ["task-001", "task-007", "task-012"],
    "index": {
      "TUI修复": ["task-001"],
      "工具替代": ["task-001", "task-007"],
      "API配置": ["task-005"]
    }
  }
  ```
- **injectable**: 标记为 true 的经验规则可在启动时注入上下文
- **容量管理**: 全量重生成，每个类型最多保留 10 条经验

#### L4 潜意识层 (Subconscious)

- **存储**: 单个 JSON 文件
- **内容结构**:
  ```json
  {
    "triggers": [
      {"keyword": "红冲逻辑变更", "l3_type": "编码任务", "l2_task": "task-033"},
      {"keyword": "消消乐小游戏", "l3_type": "编码任务", "l2_task": "task-021"},
      {"keyword": "TUI鼠标选择", "l3_type": "编码任务", "l2_task": "task-001"}
    ],
    "narrative": "用户是Rust全栈开发者，偏好极简指令。完成过Nexus红冲逻辑、消消乐游戏。对指令偏离零容忍。",
    "version": 42
  }
  ```
- **容量管理**: 覆盖式更新，触发词上限 50 个，叙事文本 500 字以内
- **注入方式**: 始终在 system prompt 中

### 2.5 召回流程

```
用户消息
  │
  ▼
LLM 基于当前上下文（L4潜意识 + 当前会话）判断：需要记忆召回吗？
  │
  ├─ 不需要 → 直接处理
  │
  └─ 需要 → 读取当前人格的索引文件
       │
       ▼
     L4 潜意识触发词匹配
       │ 命中 → 拿到 L3 类型 + L2 任务ID
       ▼
     L3 索引 → 读取该类型的经验汇总
       │ 不够 → 往下
       ▼
     L2 索引 → 读取任务摘要
       │ 不够 → 往下
       ▼
     L1 原始记忆 → 根据索引定位具体段落
       │
       └─ LLM 判断够了 or 找完了 → 结束
```

**关键**: 召回是 LLM 驱动的。LLM 自己决定：
1. 是否需要召回（基于潜意识触发词+当前上下文判断）
2. 什么时候够了（不需要遍历所有层）

### 2.6 启动时注入

```
自动注入（每轮，无需 LLM 调用）:
  ├─ L4 潜意识触发词（~50个词，几乎无开销）
  ├─ L3 中标记 injectable=true 的经验规则（~500字）
  └─ 用户画像（~100字，按人格隔离）

记忆索引（用于召回路由）:
  ├─ L3 索引（类型→L2映射）
  └─ L2 索引（任务→L1映射）
  不注入上下文，只在召回时读取
```

## 三、四步分析重构

### 3.1 新分析流程

原"四步分析"（实际8步）简化为 **四步浓缩**：

| 步骤 | 名称 | 输入 | 输出 |
|------|------|------|------|
| Step 1 | L1→L2 任务拆分 | L1 原始会话 + L2 现有索引 | 全量重生成 L2 索引 + 摘要 |
| Step 2 | L2→L3 经验抽象 | L2 摘要池 + L3 现有经验 | 全量重生成 L3 经验 + 索引 |
| Step 3 | L3→L4 触发词提取 | L3 经验 + L4 现有触发词 | 全量重生成 L4 触发词 + 叙事 |
| Step 4 | 画像+评估信息 | L1 会话 + 现有画像 | 全量重生成画像 + 评估信息 |

**每步都是全量重生成，覆盖旧文件，不追加。**

### 3.2 触发机制

- 分析间隔从配置文件读取（默认 5 轮）
- 会话结束时未分析的数据保存到 `pending_analysis.json`
- 下次启动时注入上下文 + 后台自动分析

### 3.3 LLM Prompt 核心变化

**之前**: "以下是已有条目，不要重复。请添加新发现。"
**现在**: "以下是一份现有的 {L2/L3/L4} 数据。请基于新会话内容，重新生成一份完整的、更精炼的版本。容量上限: X。"

## 四、记忆脑职责重新定义

记忆脑的四大职责：

1. **记忆保存** —— 对话存入 L1，触发分析时逐层向上浓缩
2. **层级组装** —— 每次分析时 L1→L2→L3→L4 逐层全量重生成
3. **经验生成** —— L3 层标记 `injectable=true` 的经验启动时注入
4. **评估支持** —— 为评估脑提供踩坑规则、用户偏好、历史决策模式

**记忆脑不做**: 召回决策（由主脑/LLM驱动）、评估（由评估脑负责）

## 六、实施优先级

### Phase 1: 核心金字塔骨架
- 磁盘结构重构（per-persona 目录）
- L1/L2/L3/L4 四层存储基础结构
- 新的四步浓缩分析引擎（4步全量重生成）

### Phase 2: 召回系统
- 渐进式召回引擎（L4→L3→L2→L1）
- 启动时注入（潜意识+画像+injectable经验）
- LLM 驱动的召回决策

### Phase 3: 集成与迁移
- 与主脑集成（上下文注入、召回接口）
- 与评估脑集成（评估信息提供）
- 旧数据迁移脚本
- 配置文件（analysis_interval 等可配参数）
