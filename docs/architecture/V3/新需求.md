1.还需要新增一个逻辑：要想助手能够日夜不停的工作，上下文管理尤为重要，但是现在上下文十分短小，最大也只有 1M，注定无法所有任务都在一个窗口中执行。所以需要设计一个可插拔式的上下文内容插拔器。
插拔器的作用和逻辑：
1.插拔器需要支持热插拔，也就是说模型自己能决定是否需要通过上下文插拔器动态更换上下文内容。
2.插拔器需要有增删改查的功能。
3.插拔器支持的上下文插拔有时间范围（默认为半个小时内，因为可能可以匹配上模型厂商的 kv cache 的失效时间，节省成本）
作用：当前会话中，用户给出了 3 个任务，智脑在完成一个任务后可能上下文就不够了，这个时候，保存一份完整的上下文快照以及对应的后台静默压缩的内容的快照。
然后清空上下文，保留会话开始时就已经存在的内容，然后开始第二个任务。以此类推。如果需要切换到第一个任务，只要是在插拔时间内的，就能无缝替换。
