# 最后一条用户消息持久化重试设计

## 目标

在脑 v2 的 Web 会话中恢复“重试最后一条用户消息”能力。重试后保留该用户消息，
持久化清除它之后产生的所有智脑输出和运行痕迹，再将该消息作为一次新请求重新执行。
刷新页面或重新打开会话后，不得恢复已经清除的旧结果。

## 范围

本次只恢复重试功能，不恢复用户消息编辑、整轮删除或手动选择工作区。

只有会话中最后一条用户消息显示重试入口。生成期间点击重试时，系统必须先终止当前
生成，再执行截断和重放，避免旧任务继续向已经截断的会话写入。

## 用户体验

1. 最后一条用户消息显示“重试”按钮。
2. 点击后，页面立即移除该消息之后的旧结果，并进入与新消息发送相同的生成状态。
3. 用户消息本身保留且不产生重复副本。
4. 新的主脑、副脑、群消息和工具执行过程从该消息之后重新出现。
5. 重试失败时保留用户消息，显示明确错误；已清除的旧结果不自动回填。

## 数据语义

重试边界由最后一条用户消息的稳定消息 ID 确定。系统保留该用户消息以及它之前的
可见历史，持久化清除该消息之后的：

- 主脑回复；
- 副脑和群消息事件；
- 工具调用、工具结果与中间结论；
- 本轮运行状态和未完成协作任务；
- 与被清除结果绑定的派生展示记录。

底层不可变审计日志如因架构约束不能物理删除，可以归档或建立失效边界，但所有会话
恢复、上下文装载和 UI 查询都必须排除失效数据。对用户可观察的语义等同于持久化删除。

## 架构

### Web 客户端

沿用现有 `retry_last_user_message` 消息类型。重试按钮只绑定最后一条具有稳定 ID 的
用户消息。发送重试请求后，客户端清理当前轮展示状态，并复用普通查询的生成态逻辑。

客户端不自行推断需要删除的数据库记录；服务端返回截断后的权威会话快照，客户端以
该快照重新渲染。

### WebSocket 处理层

收到重试请求后：

1. 校验目标 ID 确实属于当前会话最后一条用户消息；
2. 取消当前会话正在运行的查询；
3. 调用统一的会话截断服务；
4. 将截断前的历史恢复到主脑上下文；
5. 使用原用户消息内容启动新的查询；
6. 向客户端推送权威快照和后续进度事件。

校验和截断必须在同一会话锁或等价事务边界内完成，避免检查后又插入新消息。

### 会话与群消息持久层

会话管理器继续负责旧会话消息的截断和原消息重放。脑 v2 群消息仓储新增以会话、
房间及用户消息事件为边界的失效操作，用于清除该消息之后的房间事件、成员运行、
工具轨迹和未完成任务。

如果群消息仓储使用追加式事件模型，采用持久化 cut-off/失效标记，不修改边界之前的
事件。所有读取路径统一应用该边界。

### 任务取消

截断前必须取消与当前轮关联的运行：

- 主查询取消令牌；
- TaskEngine 中未完成的协作节点；
- 尚未完成的副脑成员运行。

取消操作应具备幂等性。重试请求重复到达时，不得产生两次并行重放。

## 错误处理

- 目标不是最后一条用户消息：拒绝请求并刷新权威会话快照。
- 会话不存在或消息 ID 无效：返回明确错误，不启动新查询。
- 截断失败：不重放消息，避免新旧结果混合。
- 截断成功但重放失败：保留截断后的历史与用户消息，允许用户再次重试。
- 取消超时：将旧运行标记失效，后续迟到事件在写入边界被丢弃。

## 测试

### 单元测试

- 仅最后一条用户消息允许重试；
- 重试保留目标消息且不追加副本；
- 目标消息之后的旧会话消息被持久化截断；
- 非最后一条消息和未知 ID 被拒绝；
- 重复重试不会产生并行运行。

### 群消息仓储测试

- 截断后房间历史不再返回边界之后的事件；
- 未完成成员运行和任务被取消或失效；
- 迟到事件无法重新出现在有效历史；
- 重新打开仓储后截断边界仍然生效。

### Web 集成测试

- 最后一条用户消息显示重试入口，其他消息不显示；
- 重试后客户端清空旧结果并使用权威快照重绘；
- 刷新页面后旧结果不会恢复；
- 新生成结果正常追加到保留的用户消息之后。

## 非目标

- 用户消息编辑；
- 用户消息或整轮手动删除；
- 任意历史消息分支重试；
- 工作区选择；
- 恢复旧常驻小说脑。
