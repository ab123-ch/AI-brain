# 结论真实性验证

## Overview
主脑输出的任何结论、观点、判断、建议都必须有证据支撑。没有证据或证据不可验证 = 可能瞎编，必须报告。

## The Iron Law
```
NO CONCLUSION WITHOUT VERIFIABLE EVIDENCE

主脑说"是 X 导致的" = 需要验证 X 是否真实存在
主脑说"我确认/发现/看到" = 需要验证声称的内容是否存在
主脑说"解决方案/建议是 Z" = 需要验证 Z 是否合理有效
主脑说"因为 A 所以 B" = 需要验证逻辑链是否成立
没有可验证证据的结论 = 可能瞎编 = 必须质疑
```

## The Gate Function
```
BEFORE 接受主脑输出：

1. IDENTIFY: 主脑声称了什么？
   - 事实陈述："日期是 X"、"库版本是 Y"
   - 分析结论："根因是 Z"、"原因是 W"
   - 建议推荐："应该用方案 A"、"最佳做法是 B"
   - 观点判断："这个设计不好"、"应该重构"

2. CHECK EVIDENCE: 主脑给出了什么证据？
   - 具体出处？（文件位置、文档链接、代码行号）
   - 引用内容？（原文片段、日志输出）
   - 验证结果？（测试输出、执行结果）
   - 推理依据？（逻辑链、数据支撑）

   IF 没有证据 → 报告"结论缺乏证据支撑"
   IF 证据不可验证 → 报告"证据无法验证真实性"

3. VERIFY EVIDENCE: 执行验证手段
   - read_file → 验证文件内容是否存在
   - grep_search → 验证日志/文本是否真实
   - bash → 验证命令执行结果
   - 环境信息 → 验证日期/系统信息

   IF 证据不存在 → 报告"主脑声称的证据不存在"
   IF 证据内容不符 → 报告"证据不支持结论"

4. CHECK LOGIC: 证据到结论的推理是否成立？
   - 主脑说"因为 A 所以 B"
   - A 真的导致 B 吗？有无其他可能性？
   - 推理链完整吗？有无跳跃假设？

   IF 逻辑断裂 → 报告"结论推理不成立"

5. ONLY THEN: 接受结论或报告问题
```

## Common Failures
| 主脑声明 | 需要验证 | 瞎编情况 |
|---------|---------|---------|
| "今天是 2025 年" | 对比环境信息中的日期 | 环境显示 2026 年 |
| "根因是 macOS 不支持" | grep 日志验证 macOS 相关错误 | 日志显示中英文偏移问题 |
| "库版本是 2.0" | read_file Cargo.toml | 实际版本是 1.5 |
| "最佳做法是 X" | 搜索官方文档/最佳实践 | X 不是官方推荐 |
| "因为 A 导致 B" | 检查逻辑链 | A 不一定导致 B |
| "我看到代码里有..." | read_file 验证 | 内容不存在 |

## Red Flags - STOP
- 主脑说"我确认/发现/看到"但没给出具体出处
- 主脑给出事实陈述但和环境信息冲突
- 主脑引用的内容无法验证（无文件位置/无链接）
- 主脑的推理链有跳跃/假设/猜测
- 主脑说"应该/可能/大概"但声称是结论
- 想着"主脑看起来很自信"就接受
- 想着"主脑应该是对的"就跳过验证

## Rationalization Prevention
| 借口 | Reality |
|------|---------|
| "主脑说找到了根因" | 验证根因证据是否真实 |
| "主脑说日期是 X" | 对比环境信息中的日期 |
| "主脑说库版本是 Y" | read_file 验证 Cargo.toml |
| "主脑给出的建议应该是对的" | 搜索验证是否是公认做法 |
| "主脑看起来很专业" | 专业 ≠ 正确，验证证据 |
| "我理解主脑的意思" | 理解 ≠ 验证，用工具验证 |
| "主脑引用了文档" | 验证文档内容和引用是否一致 |
| "这只是建议不是结论" | 建议也需要依据，否则是瞎建议 |

## Key Patterns
```
✅ [主脑说"今天是 2026-05-19"] → [对比环境信息] [See: 一致] → "日期正确"
❌ [主脑说"今天是 2025 年"] → "应该是对的" / 不对比环境

✅ [主脑说"根因是 X"] → [grep X] [See: matches] → [read_file] [See: 内容支持] → "结论有证据"
❌ [主脑说"根因是 macOS"] → [grep macOS] [See: no matches] → "应该是对的"

✅ [主脑说"建议用方案 A"] → [搜索最佳实践] [See: A 是官方推荐] → "建议合理"
❌ [主脑说"建议用方案 A"] → "主脑的建议应该没问题" / 不验证

✅ [主脑说"因为 A 所以 B"] → [检查逻辑链] [See: 推理成立] → "逻辑合理"
❌ [主脑说"因为 A 所以 B"] → "听起来有道理" / 不检查逻辑跳跃

✅ [grep 无匹配] → "评估结果-存在问题。具体问题：主脑声称的根因 macOS 不支持 无证据支撑，日志中未发现相关错误"
❌ [grep 无匹配] → "评估结果-正常"

✅ [read_file 不存在所述内容] → "评估结果-存在问题。具体问题：主脑声称的代码内容不存在，证据不支持结论"
❌ [read_file 不存在所述内容] → "相信主脑" / 不验证
```

## When To Apply
- 主脑输出包含事实陈述（日期、版本、数值）
- 主脑声称找到原因/根因/问题所在
- 主脑给出建议/方案/最佳做法
- 主脑做出判断/评价/观点
- 主脑说"我确认/发现/看到/定位到"
- 用户问题是排查/分析/咨询类

## When NOT To Apply
- 主脑输出是纯操作类（已修改文件、已执行命令）
- 主脑输出是创意类内容（写小说、设计稿）
- 主脑输出是用户已知的信息复述
- 简单的格式化/翻译/重写任务

## The Bottom Line
任何声称的结论都需要可验证的证据。没有证据或证据不可验证 = 可能瞎编，必须质疑。证据必须通过只读工具验证，不能凭"看起来对"就接受。
